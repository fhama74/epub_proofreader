# 開発状況

- Phase 1：PDF／縦書きEPUB表示・章／段落選択。
- Phase 2：本文／ルビ編集、Undo／Redo、検索置換、構造保持の書き出し。
- Phase 3：統合編集、プロジェクト途中保存・復元、確認状態、PDFページ／範囲対応、未保存入力保護。
- プロジェクト運用：EPUB読み込みごとに新規作成、永続保管、一覧・明示削除、発行版の追加・再取得。
- Phase 4：4プロバイダーのエンジン管理、明示開始、バックグラウンドジョブ、SSE、SQLite逐次保存、候補ナビ、結果一覧、承認・却下・保留、古い候補の検知、暗号化キー、料金集計、Docker運用ファイル。

次の検証は25万文字規模の全文処理と品質、クラウド実接続、Docker実機。Phase 5は下記の縮小方針に従う。

iPadの読書主体UI・PDF切替・編集切替は0.4.5で基本対応。実機確認とオフライン化は今後の課題。公開サービス化は認証と共有認可・ネットワーク制御等の追加が前提。現時点でユーザー登録・ログイン・共同編集は実装していない。

## Phase 5：縮小後の設計方針（2026-10-16）

- PDF原本画像をAIへ送信・解析する機能は実装しない。PDF原本との照合は人間が行う。
- PDFとEPUBの自動位置合わせは、PDF内に利用可能なテキストレイヤーがある場合だけ対象とする。対応の確信が得られない箇所は無理に合わせない。
- 画像のみのPDFは自動位置合わせを行わず、手動のページ移動と既存の手動対応登録を利用する。画像へのOCR処理を代替実装しない。
- 複数AIエンジンの校正結果比較、検出候補の統合、校正作業の効率化を中心に検討する。
- 同じ対象の候補を統合しても各エンジンの出所・理由・元の提案を保持する。競合する訂正を自動採用しない。
- 本文・ルビへのAI提案の反映には、引き続き人間の承認を必須とする。
- 段階導入案：保存済み候補の比較表示 → 重複候補の統合と承認履歴 → テキスト層のあるPDFとの位置合わせ。

## iPad基本対応の候補範囲

読書主体のレイアウト、EPUB／PDFの切替、編集ボタンから校正を開く動線、タッチ操作と縦横回転への対応を優先する。データはサーバー側の既存プロジェクト保存を利用する。オフライン化・端末への全書籍保存・ネイティブアプリ化は別段階。Mac上のサーバーへの接続方法とiPad Safari実機での最終確認が必要。

Phase 5機能は未実装。iPad基本対応は0.4.5で実装し、ブラウザ上で検証。Safari実機の確認は今後必要。
