# Phase 3アーキテクチャ

FastAPI／lxml／zipfile／SQLite、React／TypeScript／Vite／PDF.jsによるローカルアプリ。

## 構成

- `epub.py`：ZIP／XML解析、章・段落・ルビ、表示用コピー。
- `segments.py`：読みを除いた文字数、文範囲、300文字の自動切替。
- `editing.py`：本文・ルビ・統合編集、revision、Undo／Redo、ZIP出力と構造検証。
- `structure.py`：明示的な段落挿入・分割・結合。構造の前後スナップショット。
- `projects.py`：プロジェクト情報、確認状態・進捗、履歴再現、.eproof形式。
- `project_api.py`：プロジェクト・PDF・履歴の保存／読み込みAPI。
- `validation.py`：ローカルEPUBCheck。
- `App.tsx`：3ペイン・校正対象・表示状態・プロジェクト操作。
- `EditorDialog.tsx`：本文とその範囲のルビを一画面で編集し、未保存入力を保護。
- `useProject.ts`：メタデータ保存と編集操作の逐次化、版番号と保存状態。
- `ProjectPanel.tsx`：確認状態、PDFの対応ページ・範囲。
- `PdfPane.tsx`：ローカルPDF.js資産、表示状態、正規化範囲の選択・表示。
- `EpubPane.tsx`：縦書きの文字断片に基づく追従、手動ページ位置の復元。

## 保存モデル

`books.original`は入力ZIPを不変のまま保存する。`editing`にworking、revision、commands、cursor、history、idsを保存。`projects`にmetadata JSONとPDF BLOBを保存する。従来DBのテーブルを破棄せず追加・列移行する。

初期内部段落IDはspine・要素順で付け、構造操作で追加した段落にはUUIDを割り当てる。ids配列で再解析後も対応させ、元XHTMLには内部IDを書き込まない。結合・分割時も元のXML IDとルビを維持する。

プロジェクトメタデータは独立したversionを持つ。view、statuses、mappings、draftsを部分更新する。編集中の本文は編集revision、メタデータはproject versionで競合を検出する。ブラウザは保存・編集を逐次化し、失敗を表示する。確認済み段落の内容変更は要再確認へ切り替える。確認状態自体を本文Undoコマンドへ混在させない。

## 統合編集

本文欄は元のルビ親文字を含む段落／一文を表示する。親文字・読みの変更は同じ画面のルビ欄から受け取り、本文差分とルビ差分を一つのコマンドへまとめる。元の本文とrubyが同じrevisionであることを確認し、全差分適用・EPUB再解析後にトランザクションを確定する。失敗時は一切保存しない。

ルビ範囲は元本文のコードポイント位置。文単位編集では範囲に含まれるルビだけを許可する。複雑ルビや親文字を跨ぐ本文欄の変更は拒否する。親文字変更もtext／tailだけを更新し、rb／rt／rpと属性を保持する。

## .eproof形式（version 1）

ZIP内に次を格納する。

- `manifest.json`：format、schema_version、元ファイル名、各ファイルのSHA-256。
- `original.epub`、`working.epub`。
- `editing.json`：commands、cursor、history、revision、ids。
- `project.json`：確認状態、PDF対応、未保存入力、表示設定、予約済み空候補欄。
- `source.pdf`：添付されている場合。

読み込み時はファイル名の許可リスト・重複・暗号化・サイズ・形式版・ハッシュを検査する。編集コマンドは元EPUBから安全な本文／ルビ／構造操作で再現し、許可された文字ノードと変更結果を検証する。任意XPathや任意の構造スナップショットをそのまま信用しない。再現結果のファイル内容と作業用EPUBを比較し、Undo位置とID対応も照合する。ZIPタイムスタンプ等の違いはファイル内容と区別する。

読み込みは新しい書籍IDへ原子的に保存し、既存作業を上書きしない。ハッシュは破損と整合性の検査であり、作成者の署名ではない。

## 履歴JSON

schema_version 2は元ZIPのSHA-256、作業ZIPのハッシュ、ファイル内容のハッシュ、履歴と再現用stateを含む。インポート時は原本とファイル内容のハッシュ・再現結果を確認し、新しい作業へ復元する。version 1は表示専用の旧形式で、再現データがないため復元しない。

## 未保存入力と表示状態

入力は段落IDと文番号をキーに、元revision・元本文・入力本文・ルビ・理由を保存。入力時にlocalStorageへ保護し、デバウンスしてSQLiteにも保存する。閉じる際は保存完了を待つ。本文確定後に下書きを消す。古いrevisionの下書きは自動適用せず比較用に表示する。

表示状態は章・段落／文、文字サイズ、本文横スクロール、PDFページ・倍率・スクロール、左右幅・折りたたみ。本文の手動ページ位置は再開時に復元し、新しい校正対象へ移動した際は追従に戻る。縦書きのRange.getClientRects()で全文断片を評価し、収まる対象は全体、幅を超える対象は先頭を表示する。

## PDF対応

PDFはSQLiteと.eproofへ保存する。ページと正規化矩形[x1,y1,x2,y2]を段落に紐付け、複数ページ・範囲を許可する。PDF SHA-256が一致する対応だけを表示し、別PDFの対応は明示する。分割時は元対応を新しい段落にも引き継ぎ、結合時は対応を統合する。構造編集後は原本との対応を再確認する。

## 安全性・出力

EPUBのパス・重複・展開サイズ・manifest・XML実体を検証し、ディスクには展開しない。プレビューは許可要素だけをコピーし、元script／style／イベント／外部画像を実行しない。sandboxはallow-same-originのみ、CSPで外部通信を制限する。

元EPUBを更新せず、変更XHTMLを再直列化して出力する。未変更ファイル、ファイル一覧、XML ID、manifest、spine、目次、メタデータ、綴じ方向を比較する。構造操作のあるファイルは適用中のスナップショットを期待構造として比較する。mimetypeは先頭・無圧縮。EPUBCheckはローカルCLI／JARで60秒以内に実行し、未設定・失敗を成功と区別する。

PDF.jsのWASM／CMap／標準フォントは同じ版からローカル配信し、CDNを使用しない。AI通信は承認操作とは分離したバックエンドAdapterで行う。[Phase 4設計](AI.md)を参照。


## Phase 4追加

プロジェクト一覧・永久保持・版番号付き発行に加え、AI設定・ジョブ・結果・料金を同じSQLiteへ追加。既存のBookと安全な編集を使い、本文・ルビの承認は既存履歴へsource=aiで記録する。詳細は[AI設計](AI.md)。

### XHTML単位の作業保存（0.5.6）

編集・ルビ修正・段落操作・Undo/RedoではEPUBを組み立てない。保存済みのEPUBを基準として保持し、変更したXHTMLだけをライブラリDBのediting_filesへ保存する。通常の追加編集では基準EPUBのBLOBも書き直さない。元のEPUB・既存の作業用EPUB・履歴は移行時に置き換えず、そのまま基準として読み込む。全Undo時は取り込み時の内容へ戻し、差分を除去する。

解析済みの書籍データを再利用し、変更したXHTMLの章だけをXML検証・段落/文/ルビの再計算にかける。キャッシュしたXMLを直接書き換えず、編集対象のツリーを複製する。キャッシュがなくなった場合は、保存した基準EPUBとXHTML差分から再開できる。XML宣言・DOCTYPE・処理命令も保持する。

EPUBの組み立てと全体検証は、EPUB発行、EPUB書き出し、作業バックアップや履歴の書き出し時に行う。既存の.eproof形式を維持し、作業用EPUBはその時点で組み立てて含める。発行時のEPUBCheckは従来どおり。画面には引き続き全章の概要を返し、表示中の章のHTMLを再取得するため、通信・画面の再配置時間は残る。

独立コピー（1,867段落・27章）で文字編集2回を比較：保存APIは従来0.47〜0.48秒、変更後約0.07秒。章プレビュー取得は従来0.13〜0.19秒、変更後約0.003秒。編集時のZIP組み立ては2回から0回。ローカルでキャッシュが利用できる条件の参考値で、ブラウザー描画やネットワークの待ち時間は含まない。
